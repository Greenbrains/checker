# Fact-Checker Agent v1.0

Мультиагентная система автоматического фактчекинга с верификацией по первоисточникам.

## 📋 Описание

Fact-Checker Agent — это система для автоматической проверки фактов в текстах с использованием нескольких AI-моделей (чекеров) и инструментов веб-поиска. Система находит фактические ошибки, проверяет числа, даты, названия и утверждения по авторитетным источникам.

## 🔧 Возможности

- **Мультиагентная проверка**: несколько независимых чекеров на разных моделях
- **Веб-верификация**: автоматический поиск и чтение первоисточников
- **Арбитраж**: интеллектуальное сведение отчётов чекеров в итоговый отчёт
- **Поддержка русского языка**: оптимизирован для проверки русскоязычных материалов
- **Детальная логика**: полный трейсинг каждого шага проверки

## 📦 Установка

```bash
# Клонирование репозитория
git clone <repository-url>
cd factcheck-agent

# Установка зависимостей
pip install -r requirements.txt

# Настройка переменных окружения
cp .env.example .env
# Отредактируйте .env, указав необходимые API-ключи
```

## ⚙️ Конфигурация

Создайте файл `.env` со следующими переменными:

```env
# Провайдер моделей (router или yandex)
default_provider=router

# API-ключи
ROUTER_AI_KEY=your_router_api_key
YANDEX_API_KEY=your_yandex_api_key
YANDEX_FOLDER_ID=your_folder_id

# Модели
ROUTER_MODEL=z-ai/glm-5.3-flash
YANDEX_MODEL_ROUTER=aliceai-llm-flash/latest
YANDEX_MODEL_AGENT=qwen3.6-35b-a3b/latest

# Чекеры (список моделей через запятую)
CHECKER_MODELS=z-ai/glm-5.3-flash,openai/gpt-4o-mini,google/gemini-3.5-flash-lite

# Пути
LOG_FILE=logs.txt
OUTPUT_DIR=output
INPUT_DIR=input
```

## 🚀 Использование

### Базовый запуск

```bash
python main.py
```

### Проверка конкретного файла

Поместите проверяемый текст в папку `input/` и запустите:

```bash
python main.py input/your_file.txt
```

### Настройка количества чекеров

В `.env` укажите нужные модели:

```env
# Один чекер (быстро)
CHECKER_MODELS=z-ai/glm-5.3-flash

# Два чекера (баланс)
CHECKER_MODELS=z-ai/glm-5.3-flash,openai/gpt-4o-mini

# Три чекера (максимальная точность)
CHECKER_MODELS=z-ai/glm-5.3-flash,openai/gpt-4o-mini,google/gemini-3.5-flash-lite
```

## 📊 Формат отчётов

### Индивидуальный отчёт чекера

Каждый чекер создаёт файл `check_{number}_{model}.md`:

```markdown
# Отчёт чекера 1 (z-ai/glm-5.3-flash)

## 1. Ошибки

**Предложение 3**: «Распространение фейковых новостей...»
- Тип: число
- Проблема: указано 49 пунктов, фактически 39
- Источник: https://wciom.ru/...

## 2. Проверено без ошибок

- Интегральный индекс: 21 пункт ✓
- Утечка данных: 47 пунктов ✓

## 3. Вывод

Материал содержит 2 ошибки в 3 предложениях...
```

### Итоговый отчёт

Файл `check.md` содержит сводную таблицу и арбитраж расхождений:

```markdown
# Итоговый отчёт фактчека

## 1. Сводная таблица ошибок

| № | Цитата | Тип | Корректно | Чекеры | Источники |
|---|--------|-----|-----------|--------|-----------|
| 1 | ...    | число | 39 п. | 2/2 | wciom.ru |

## 2. Детали по каждой ошибке
...

## 3. Расхождения между чекерами
...

## 4. Тезисы без ошибок
...

## 5. Вывод
...
```

## 🛠 Инструменты

Система использует следующие инструменты:

| Инструмент | Описание |
|------------|----------|
| `web_search` | Поиск информации в интернете |
| `web_read` | Чтение содержимого веб-страниц |
| `code_execute` | Выполнение Python-кода для анализа данных |
| `file_read` | Чтение входных файлов |
| `file_write` | Запись отчётов |

## 🔍 Примеры проверки

### Проверка статистики

```
Вход: «По данным ВЦИОМ, 47% россиян боятся утечки данных»
Проверка: Поиск первоисточника на wciom.ru
Результат: ✓ Подтверждено (47 пунктов индекса)
```

### Проверка названий организаций

```
Вход: «Всероссийского центра исследования общественного мнения»
Проверка: Сверка с официальным названием
Результат: ✗ Ошибка (правильно: «изучения», а не «исследования»)
```

### Проверка динамики

```
Вход: «Тревожность снизилась с 18 до 13 пунктов»
Проверка: Чтение первоисточника
Результат: ✗ Ошибка направления (на самом деле выросла с 13 до 18)
```

## 🔄 Workflow

1. **Загрузка документа**: чтение текста из `input/`
2. **Запуск чекеров**: параллельная проверка N моделями
3. **Верификация**: каждый чекер использует `web_search` и `web_read`
4. **Арбитраж**: модель-арбитр сводит отчёты
5. **Вывод**: сохранение `check.md` и индивидуальных отчётов

## ⚠️ Ограничения

- **Таймаут поиска**: 10 секунд на запрос
- **Максимум итераций**: 8-10 на чекера
- **Размер ответа**: до 15000 символов на страницу
- **Зависимость от API**: требуется стабильный интернет

## 🛡 Безопасность

- API-ключи хранятся в `.env` (не коммитить в git!)
- Логи не содержат чувствительных данных
- Веб-запросы через HTTPS
