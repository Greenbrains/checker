# Fact-Checker Agent v3.0

Мультиагентная система автоматического фактчекинга с верификацией по первоисточникам.  
Поддерживает три режима работы: классический параллельный (v1), конвейерный claims-based (v2) и стейт-ориентированный пайплайн с эмбеддером (v3).

---

## Возможности

- **Мультиагентная проверка** — несколько независимых чекеров на разных моделях
- **Веб-верификация** — автоматический поиск первоисточников (ddgs: DuckDuckGo → Brave → Google → Yahoo)
- **Песочница для расчётов** — Python-интерпретатор для проверки чисел, дат, формул
- **Эмбеддер** — нарезка больших документов на чанки по 7-10 предложений для обработки в контекстном окне
- **Арбитраж** — сведение отчётов чекеров в итоговый structured-отчёт
- **Три пайплайна** — v1 (быстрый старт), v2 (claims-based), v3 (стейт-ориентированный с эмбеддером)
- **Оптимизация для русскоязычных материалов** — регион `ru-ru`, приоритет `.ru`/`.рф` источников

## Архитектура

### Пайплайн v1 — параллельные чекеры

Простой и быстрый режим. Каждый чекер независимо читает весь материал, ищет источники и составляет отчёт. Арбитр сводит отчёты в итоговый `check.md`.

```
               ┌─────────────────────────────┐
               │    FactcheckOrchestrator     │
               │         (v1)                │
               └──────────────┬──────────────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
       ┌────────────┐  ┌────────────┐  ┌────────────┐
       │ Checker 1  │  │ Checker 2  │  │ Checker N  │
       │ (модель A) │  │ (модель B) │  │ (модель C) │
       └─────┬──────┘  └─────┬──────┘  └─────┬──────┘
             │               │               │
             │  web_search, code_execute     │
             └───────────────┼───────────────┘
                             ▼
                    ┌─────────────────┐
                    │     Arbiter     │
                    │  (сведение      │
                    │   отчётов)      │
                    └────────┬────────┘
                             ▼
                    ┌─────────────────┐
                    │   check.md      │
                    │ + check_N_*.md  │
                    └─────────────────┘
```

Инструменты каждого чекера: `web_search`, `code_execute`.  
Арбитр работает без инструментов — только синтез на основе отчётов.

### Пайплайн v2 — claims-based конвейер

Декомпозирует задачу: сначала извлекает атомарные утверждения, затем маршрутизирует их по специализированным верификаторам.

```
  ┌─────────────────────────────────────────────────────────┐
  │              FactcheckOrchestratorV2                    │
  └─────────────────────────────────────────────────────────┘

  1. EXTRACT
     ┌──────────────┐
     │  Extractor   │  навык: fact-extract
     │              │  → список claims в JSON (тип, source_hint, id)
     └──────┬───────┘
            │
  2. DISPATCH (чистый Python, без LLM)
     claims.py::dispatch()
     → кластеры по типу и источнику:
       web:<domain>, web:other, math, grammar, consistency
            │
  3. VERIFY (параллельно по кластерам)
            │
     ┌──────┴─────────────────────────────────┐
     │                                        │
     ▼  web-кластер                           ▼  math / grammar
  ┌──────────┐   ┌──────────────┐          ┌──────────────┐
  │  Finder  │   │ Source Cache │          │ verify-math  │  code_execute
  │verify-web│──▶│ (url→text)   │          │verify-grammar│  (без сети)
  └──────────┘   └──────┬───────┘          └──────────────┘
                        │
                 ┌──────▼───────┐
                 │   Reader     │  навык: verify-read
                 │ verify-read  │  работает только с текстом из кэша
                 └──────────────┘

     consistency-claims → напрямую арбитру (внешний поиск не нужен)

  4. ARBITRATE
     ┌──────────────┐
     │   Arbiter    │  навык: fact-arbiter
     │              │  claims + verdicts + consistency → итоговый отчёт
     └──────┬───────┘
            ▼
     output/
     ├── check.md          ← итоговый отчёт для пользователя
     ├── v2_claims.json    ← дамп извлечённых утверждений
     └── v2_verdicts.json  ← сырые вердикты верификаторов
```

#### Распределение инструментов в v2

| Роль | Навык | Инструменты |
|---|---|---|
| Extractor | `fact-extract` | — |
| Finder | `verify-web` | `web_search`, `web_read` |
| Reader | `verify-read` | — (текст из source_cache) |
| Math | `verify-math` | `code_execute` |
| Grammar | `verify-grammar` | — |
| Arbiter | `fact-arbiter` | — |

#### Source Cache

Когда Finder находит URL, оркестратор скачивает страницы через `web_read` и кэширует их (`url → {text, ts}`). Reader получает текст из кэша — без повторных HTTP-запросов. Это исключает таймауты и 403-ошибки при повторном обращении к одному источнику, а также экономит токены: страница читается один раз.

### Пайплайн v3 — стейт-ориентированный с эмбеддером

Оптимизирован для работы с большими документами (курсовые, дипломы, отчёты на 20+ страниц). Оркестратор (он же арбитр) управляет последовательными стейтами: эмбеддер → чекеры → финальный отчёт.

```
  ┌─────────────────────────────────────────────────────────┐
  │           FactcheckOrchestratorV3 (Arbiter)             │
  │  Управляет стейтами, назначает модели субагентам        │
  └─────────────────────────────────────────────────────────┘

  STATE 1: EMBEDDER
     ┌──────────────┐
     │  Embedder    │  Читает входной документ (pdf, docx, pptx, xlsx, txt, img)
     │              │  Извлекает текст → режет на чанки по 7-10 предложений
     │              │  Сохраняет как N markdown-файлов с нумерацией и контекстом
     └──────┬───────┘
            │  Освобождает память после завершения
            ▼
     output/chunks/
     ├── chunk_001.md
     ├── chunk_002.md
     └── ...

  STATE 2: CHECKERS (параллельно по моделям)
     ┌───────────────────────────────────────────────────────┐
     │  Checker 1 (модель A)  │  Checker 2 (модель B)  │ ... │
     │  Читает чанки по шагам │  Читает чанки по шагам │     │
     │  Бюджет итераций: 8    │  Бюджет итераций: 8    │     │
     │  web_search, code_exec │  web_search, code_exec │     │
     └───────────┬────────────┴───────────┬────────────┘
                 │                        │
                 │  Отчёт по чанкам       │  Отчёт по чанкам
                 └────────────┬───────────┘
                              ▼
                        Освобождение памяти

  STATE 3: ARBITER (финальный отчёт)
     ┌──────────────┐
     │   Arbiter    │  Сводит отчёты чекеров
     │              │  Генерирует краткую таблицу ошибок
     │              │  Добавляет ссылки на источники по чекерам
     │              │  Выводы по каждому чекеру (без погружения)
     └──────┬───────┘
            ▼
     output/
     ├── check.md              ← итоговый краткий отчёт
     ├── check_{N}_{model}.md  ← полные отчёты чекеров
     └── v3_chunks_meta.json   ← метаданные чанков
```

#### Распределение инструментов в v3

| Роль | Инструменты | Описание |
|---|---|---|
| Embedder | — | Только извлечение текста и нарезка (без LLM-инструментов) |
| Checker | `web_search`, `code_execute` | Поиск фактов, проверка расчётов |
| Arbiter | — | Синтез итогового отчёта |

#### Нарезка на чанки

Эмбеддер разбивает текст на чанки по **7-10 предложений** (оптимально: ~5-8 фактов на чанк). Это позволяет:
- Не переполнять контекстное окно модели
- Обрабатывать документы на 20+ страниц без потери качества
- Параллелить проверку разных частей документа

Каждый чанк сохраняется как отдельный `.md`-файл с мета-контекстом:
```markdown
<!-- chunk_id: 001 | total_chunks: 15 | sentences: 8 -->
[Текст чанка...]
```

#### Решение проблемы с большими документами

В v3 каждый чекер работает **только со своим набором чанков** и имеет ограниченный бюджет итераций (по умолчанию 8). Это предотвращает превышение лимитов API даже для курсовых на 20 листов:
- Документ разбит на 15-30 чанков
- Чекер обрабатывает чанки последовательно, освобождая память после каждого
- Общий бюджет итераций распределяется между чанками пропорционально

```env

YANDEX_FOLDER_ID=your_folder_id           # только для yandex

ROUTER_MODEL=z-ai/glm-5.3-flash
YANDEX_MODEL_ROUTER=aliceai-llm-flash/latest
YANDEX_MODEL_AGENT=qwen3.6-35b-a3b/latest

# Чекеры (2–4 модели через запятую)
CHECKER_MODELS=z-ai/glm-5.3-flash,google/gemini-3.5-flash-lite,inception/mercury-2.5

# Арбитр (по умолчанию = model_agent активного провайдера)
ARBITER_MODEL=

# Пайплайн: v1, v2 или v3
PIPELINE_VERSION=v1

# Бюджет итераций одного чекера
CHECKER_MAX_ITERATIONS=8

# Пути
INPUT_DIR=input
OUTPUT_DIR=output
LOG_FILE=logs.txt
```

## Формат отчёта

### Индивидуальный отчёт чекера (v1/v3): `check_{N}_{model}.md`

```markdown
# Отчёт чекера 1 (z-ai/glm-5.3-flash)

## 1. Ошибки

**Предложение 3**: «...47 пунктов...»
- Тип: число
- Проблема: указано 47, фактически 39
- Источник: https://wciom.ru/...

## 2. Проверено без ошибок
## 3. Вывод
```

### Итоговый отчёт: `check.md`

```markdown
# Итоговый отчёт фактчека

## 1. Сводная таблица ошибок
| № | Цитата | Тип | Корректно | Чекеры | Источники |

## 2. Детали по каждой ошибке
## 3. Расхождения между чекерами
## 4. Тезисы без ошибок; непроверяемые тезисы
## 5. Вывод

---
# Приложение. Первичные отчёты чекеров  (v1/v3)
# Приложение A. Claims / B. Вердикты / C. Source cache  (v2)
# Приложение D. Чанки и метаданные  (v3)
```

## Инструменты

| Инструмент | Описание |
|---|---|
| `web_search` | Метасерч ddgs: DuckDuckGo → Brave → Google → Yahoo, регион `ru-ru` |
| `code_execute` | Python-песочница для проверки расчётов, дат, таблиц |
| `load_skill` | Загрузка SKILL.md-инструкции по имени навыка |

**Примечание**: инструмент `web_read` удалён в v3. Чтение страниц осуществляется только через кэш источников (v2) или напрямую через `web_search` + сниппеты.

Wikipedia заблокирована в РФ (403) — отфильтровывается автоматически.

## Примеры проверок

**Статистика**
```
Вход:     «47% россиян боятся утечки данных»
Проверка: поиск первоисточника на wciom.ru
Результат: ✓ подтверждено
```

**Официальное название**
```
Вход:     «Всероссийский центр исследования общественного мнения»
Результат: ✗ ошибка — правильно «изучения», а не «исследования»
```

**Направление динамики**
```
Вход:     «тревожность снизилась с 18 до 13 пунктов»
Результат: ✗ ошибка — фактически выросла с 13 до 18
```

## Ограничения

- Таймаут HTTP-запроса: 20 секунд (3 ретрая)
- Бюджет итераций чекера: `CHECKER_MAX_ITERATIONS` (по умолчанию 8) + 1 финальный без инструментов
- Кэш источников v2: до 3 URL на кластер, до 8000 символов на страницу
- Нарезка чанков v3: 7-10 предложений на чанк (~5-8 фактов)
- Wikipedia и ряд зарубежных `.org` недоступны из РФ

---

## Безопасность

- API-ключи только в `.env` — не коммитить в git (`echo ".env" >> .gitignore`)
- `code_execute` блокирует `subprocess`, `eval`, `exec`, запись файлов и `shutil.rmtree`
- Логи не содержат значений ключей — только имена переменных
