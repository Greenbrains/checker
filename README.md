# Fact-Checker Agent v3.1

Мультиагентная система автоматического фактчекинга с верификацией по первоисточникам.  
Поддерживает четыре режима работы: классический параллельный (v1), конвейерный claims-based (v2), стейт-ориентированный пайплайн с эмбеддером (v3) и граф-ориентированный пайплайн с оптимизацией токенов (v3.1).

---

## Возможности

- **Мультиагентная проверка** — несколько независимых чекеров на разных моделях
- **Веб-верификация** — автоматический поиск первоисточников (ddgs: DuckDuckGo → Brave → Google → Yahoo)
- **Песочница для расчётов** — Python-интерпретатор для проверки чисел, дат, формул
- **Граф состояний** — явная модель состояний с условными переходами (v3.1)
- **Кеш источников** — общий кеш между чекерами для экономии запросов (v3.1)
- **Дедупликация фактов** — извлечение уникальных фактов перед проверкой (v3.1)
- **Программная нарезка** — разбиение на чанки без LLM (v3.1)
- **Суммаризация перед арбитражем** — передача кратких резюме вместо полных отчётов (v3.1)
- **Оптимизация для русскоязычных материалов** — регион `ru-ru`, приоритет `.ru`/`.рф` источников

## Архитектура

### Пайплайн v1 — параллельные чекеры

Простой и быстрый режим. Каждый чекер независимо читает весь материал, ищет источники и составляет отчёт. Арбитр сводит отчёты в итоговый `check.md`.

### Пайплайн v2 — claims-based конвейер

Декомпозирует задачу: сначала извлекает атомарные утверждения, затем маршрутизирует их по специализированным верификаторам.

### Пайплайн v3 — стейт-ориентированный с эмбеддером

Оптимизирован для работы с большими документами (курсовые, дипломы, отчёты на 20+ страниц). Оркестратор управляет последовательными стейтами: эмбеддер → чекеры → финальный отчёт.

### Пайплайн v3.1 — граф-ориентированный с оптимизацией

Рефакторинг v3 с устранением ключевых проблем:

| Проблема v3 | Решение v3.1 |
|-------------|--------------|
| Оркестратор перегружен логикой | Тонкий оркестратор, логика в узлах графа |
| Чекер пересоздаётся на каждый чанк | Один чекер обрабатывает все свои факты |
| Бюджет итераций мал (3 на чанк) | Увеличен до 5-6 на набор фактов |
| Нет кеша источников между чекерами | Общий `SourceCache` для всех чекеров |
| Эмбеддер как LLM для нарезки | Программная нарезка (без LLM) |
| Арбитр получает все отчёты целиком | Суммаризация перед арбитражем |
| Нет дедупликации фактов | Дедупликация + распределение по чекерам |
| Пустые ответы съедают итерации | Исправлено в `BaseAgent.run()` |

## Конфигурация `.env`

```env
# Провайдер: router или yandex
DEFAULT_PROVIDER=router

# API-ключи
ROUTER_AI_KEY=your_router_api_key
YANDEX_API_KEY=your_yandex_api_key
YANDEX_FOLDER_ID=your_folder_id

# Базовые модели
ROUTER_MODEL=z-ai/glm-5.3-flash
YANDEX_MODEL_ROUTER=aliceai-llm-flash/latest
YANDEX_MODEL_AGENT=qwen3.6-35b-a3b/latest

# Чекеры (2–4 модели через запятую)
CHECKER_MODELS=z-ai/glm-5.3-flash,google/gemini-3.5-flash-lite,inception/mercury-2.5

# Арбитр (по умолчанию = model_agent активного провайдера)
ARBITER_MODEL=

# Пайплайн: v1, v2, v3 или v3.1
PIPELINE_VERSION=v1

# Бюджет итераций одного чекера
CHECKER_MAX_ITERATIONS=8

# Порог нарезки на чанки (символы, v3.1)
CHUNKING_THRESHOLD=2000

# Пути
INPUT_DIR=input
OUTPUT_DIR=output
LOG_FILE=logs.txt
```

## Формат отчёта

### Индивидуальный отчёт чекера (v1/v3/v3.1): `check_{N}_{model}.md`

```markdown
# Отчёт чекера 1 (z-ai/glm-5.3-flash)

## 1. Ошибки

**Предложение 3**: «...47 пунктов...»
- Тип: число
- Проблема: указано 47, фактически 39
- Источник: https://wciom.ru/...

## 2. Проверено без ошибок
## 3. Вывод
```

### Итоговый отчёт: `check.md`

```markdown
# Итоговый отчёт фактчека

## 1. Сводная таблица ошибок
| № | Цитата | Тип | Корректно | Чекеры | Источники |

## 2. Детали по каждой ошибке
## 3. Расхождения между чекерами
## 4. Тезисы без ошибок; непроверяемые тезисы
## 5. Вывод

---
# Приложение. Первичные отчёты чекеров (v1/v3/v3.1)
# Приложение A. Claims / B. Вердикты / C. Source cache (v2)
# Приложение D. Чанки и метаданные (v3)
# Приложение E. Суммаризированные отчёты (v3.1)
```

## Инструменты

| Инструмент | Описание |
|------------|----------|
| `web_search` | Метасерч ddgs: DuckDuckGo → Brave → Google → Yahoo, регион `ru-ru` |
| `code_execute` | Python-песочница для проверки расчётов, дат, таблиц |
| `load_skill` | Загрузка SKILL.md-инструкции по имени навыка |

**Примечание**: инструмент `web_read` удалён в v3. Чтение страниц осуществляется только через кэш источников (v2) или напрямую через `web_search` + сниппеты.

Wikipedia заблокирована в РФ (403) — отфильтровывается автоматически.

## Примеры проверок

**Статистика**
```
Вход:     «47% россиян боятся утечки данных»
Проверка: поиск первоисточника на wciom.ru
Результат: ✓ подтверждено
```

**Официальное название**
```
Вход:     «Всероссийский центр исследования общественного мнения»
Результат: ✗ ошибка — правильно «изучения», а не «исследования»
```

**Направление динамики**
```
Вход:     «тревожность снизилась с 18 до 13 пунктов»
Результат: ✗ ошибка — фактически выросла с 13 до 18
```

## Ограничения

- Таймаут HTTP-запроса: 20 секунд (3 ретрая)
- Бюджет итераций чекера: `CHECKER_MAX_ITERATIONS` (по умолчанию 8) + 1 финальный без инструментов
- Кэш источников v2: до 3 URL на кластер, до 8000 символов на страницу
- Нарезка чанков v3: 7-10 предложений на чанк (~5-8 фактов)
- Нарезка чанков v3.1: программная, порог `CHUNKING_THRESHOLD` символов
- Wikipedia и ряд зарубежных `.org` недоступны из РФ

## Безопасность

- API-ключи только в `.env` — не коммитить в git (`echo ".env" >> .gitignore`)
- `code_execute` блокирует `subprocess`, `eval`, `exec`, запись файлов и `shutil.rmtree`
- Логи не содержат значений ключей — только имена переменных

## Ключевые отличия v3.1 от v3

| Аспект | v3 | v3.1 |
|--------|-----|------|
| **Архитектура** | Монолитный оркестратор | Граф состояний + тонкий оркестратор |
| **Состояние** | В оркестраторе | В `PipelineContext` |
| **Создание чекеров** | Новый на каждый чанк | Один на все чанки |
| **Бюджет итераций** | 3 на чанк | 5-6 на набор фактов |
| **Кеш источников** | ❌ | ✅ Общий между чекерами |
| **Нарезка чанков** | LLM-эмбеддер | Программная (без LLM) |
| **Дедупликация фактов** | ❌ | ✅ Перед проверкой |
| **Суммаризация** | ❌ | ✅ Перед арбитражем |
| **Экономия токенов** | — | ~60-75% на системных промптах |
