# Pipeline V3 — State-based Fact-Checking

## Архитектура

```
┌─────────────┐
│ Оркестратор │ (он же Арбитр)
└──────┬──────┘
       │
   ┌───▼───────────────────────────────────────┐
   │  СТЕЙТ 1: ЭМБЕДДЕР                        │
   │  - Извлекает текст из файлов              │
   │  - Режет на чанки по 7-10 предложений     │
   │  - Сохраняет чанки в output/chunks/*.md   │
   └───────────────┬───────────────────────────┘
                   │
   ┌───────────────▼───────────────────────────┐
   │  СТЕЙТ 2: ЧЕКЕРЫ (параллельно по моделям) │
   │  - Каждый чекер читает ВСЕ чанки          │
   │  - Бюджет итераций делится на чанки       │
   │  - Инструменты: web_search, code_execute  │
   │  - Отчёт по каждому чанку                 │
   └───────────────┬───────────────────────────┘
                   │
   ┌───────────────▼───────────────────────────┐
   │  СТЕЙТ 3: АРБИТР                          │
   │  - Сводит отчёты всех чекеров             │
   │  - Краткий формат: таблица + ссылки       │
   │  - Выводы по каждому чекеру               │
   └───────────────┬───────────────────────────┘
                   │
            ┌──────▼──────┐
            │ check.md    │ (итоговый отчёт)
            └─────────────┘
```

## Ключевые изменения vs V1/V2

### 1. Эмбеддер (Стейт 1)
- **Зачем**: Большие документы (курсовые 20+ страниц) не помещаются в контекстное окно
- **Как**: Модель-эмбеддер режет текст на чанки по 7-10 предложений (~8 фактов на чанк)
- **Fallback**: Если модель недоступна — простая разбивка по предложениям
- **Выход**: Файлы `output/chunks/chunk_N.md`

### 2. Чекеры (Стейт 2)
- **Оптимизация итераций**: Бюджет делится на чанки (`max_iter // 5`)
  - Пример: 9 итераций всего → ~2 итерации на чанк при 5 чанках
  - prevents вылет по лимиту на больших документах
- **Приоритизация фактов**: Критичные (числа, даты, названия) → второстепенные
- **Инструменты**: 
  - ✅ `web_search` — поиск источников
  - ✅ `code_execute` — расчёты, таблицы pandas
  - ❌ `web_read` — удалён (не использовался, лишние токены)

### 3. Арбитр (Стейт 3)
- **Краткий формат** отчёта:
  1. Сводная таблица ошибок
  2. Ссылки по чекерам
  3. Выводы по чекерам (без погружения)
  4. Общий итог

## Запуск

```bash

```

## Структура выходных файлов

```
output/
├── check.md                          # Итоговый отчёт (арбитр + приложения)
├── chunks/
│   ├── chunk_1.md                    # Чанки текста
│   ├── chunk_2.md
│   └── ...
├── check_1_model-name_chunk1.md      # Отчёты чекеров по чанкам
├── check_1_model-name_chunk2.md
├── check_2_other-model_chunk1.md
└── ...
```

## Обработка больших документов

| Документ        | Страниц | Чанков | Итераций на чекера | Время* |
|-----------------|---------|--------|--------------------|--------|
| Короткая статья | 1-2     | 1-2    | 4-5                | 2-3 мин |
| Курсовая        | 7-10    | 5-8    | 2-3 на чанк        | 10-15 мин |
| Диплом          | 20+     | 15-20  | 1-2 на чанк        | 20-30 мин |

*Время зависит от доступности API и количества чекеров

## Преимущества V3

1. **Масштабируемость**: Работает с документами любого размера
2. **Экономия токенов**: Чекеры получают только текст, не тратят токены на file_read
3. **Надёжность**: Fallback на простую разбивку при сбое эмбедера
4. **Прозрачность**: Чанки сохраняются для аудита
5. **Краткость**: Арбитр даёт сжатый итог без потери качества

## Ограничения

- Эмбеддер использует дополнительную итерацию модели (+токены)
- Чекеры работают последовательно по чанкам (не параллельно внутри чекера)
- При очень больших документах (50+ страниц) может потребоваться увеличение `checker_max_iterations`
